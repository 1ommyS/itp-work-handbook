# Алгоритмы и live coding

Алгоритмический отбор встречается в некоторых крупных технологических компаниях и отдельных командах. Из этого не следует, что он обязателен для любой вакансии разработчика. Например, [Яндекс описывает алгоритмические задачи в процессе найма бэкенда](https://yandex.ru/jobs/interview/backend). В другом процессе live coding может быть реализацией API, исправлением бага или SQL-запросом. Уточняйте формат у конкретного работодателя.

## Сначала проверьте стартовую точку

Выберите незнакомую несложную задачу на массив и задачу на хеш-таблицу. Решите без подсказок, проговаривая требования, сложность и тесты. Затем посмотрите, где остановились: не распознали структуру, не вывели алгоритм, не смогли написать код или не заметили крайний случай. Эти проблемы требуют разной тренировки.

Не меняйте основной язык ради рейтинга платформы. Используйте язык, которым владеете и который разрешён на интервью. Повторите библиотечные коллекции, сортировку, сравнение, обработку пустых значений и особенности чисел.

## Карта паттернов

| Паттерн | Когда полезен | Проверочный вопрос |
| --- | --- | --- |
| Hash map / set | Частоты, поиск пары, дубликаты | Что хранится в ключе и сколько памяти потребуется? |
| Two pointers | Отсортированные последовательности, движение с двух концов | Почему указатель можно сдвинуть, не пропустив ответ? |
| Sliding window | Подотрезок с ограничением | Когда окно можно сжать и поддерживать условие? |
| Prefix sums | Повторные суммы диапазонов | Где нулевой префикс и как избежать ошибки границ? |
| Binary search | Упорядоченность или монотонный ответ | Какой инвариант и что происходит на пустом диапазоне? |
| Stack / queue | Скобки, обход, монотонная структура | Что означает элемент и когда удаляется? |
| BFS / DFS | Деревья, графы, связность | Как отмечаются посещённые вершины, есть ли циклы? |
| Heap | Лучшие k элементов, приоритеты | Почему не полная сортировка? |
| Intervals | Пересечения, объединение, расписание | Как определено касание границ? |
| Backtracking | Перебор вариантов с ограничениями | Где отсечение и восстановление состояния? |
| Dynamic programming | Повторяющиеся подзадачи | Что означает состояние, переход и базовый случай? |

Сложные динамические задачи и соревнования добавляйте, только если этого требует целевой отбор или уже закрыта база. Набор паттернов — план обучения, не обещание угадать вопросы.

## Сколько задач решать

Универсального количества нет. В качестве **редакционного стартового плана** возьмите 25–40 задач на основные паттерны и повторите ошибочные через несколько дней. Если алгоритмы занимают важное место в целевом отборе, расширяйте набор после диагностики. Это не минимальный проходной порог и не статистика успешных кандидатов.

Одна задача засчитывается как освоенная, когда вы можете объяснить решение и заново написать его без просмотра. Десять просмотренных разборов не заменяют самостоятельную попытку. После разумного лимита времени изучите подсказку, запишите недостающую идею и вернитесь позже к чистому решению.

Для практики подходят [CodeRun](https://coderun.yandex.ru/) и [LeetCode](https://leetcode.com/studyplan/top-interview-150/). У LeetCode есть план Top Interview 150, но не нужно откладывать отклики до окончания всего списка. Ссылки проверены 6 сентября 2026 года.

## Поведение на секции

1. Перескажите задачу. Уточните размер входа, повторы, пустой ввод, диапазон чисел и ожидаемый формат результата.
2. Покажите простой корректный подход и оцените время/память.
3. Предложите улучшение и объясните его идею до кода.
4. Согласуйте решение с интервьюером. Пишите читаемо, называйте инвариант.
5. Проверьте обычный пример, пустой/минимальный ввод, повторения и границы.
6. Сравните итоговую сложность с требованиями и обозначьте ограничения.

Если застряли: «Текущий вариант квадратичный. Повторный поиск можно заменить таблицей, но нужно аккуратно обработать дубликаты. Проверю на таком примере…» Это полезнее молчания. Полученную подсказку используйте открыто; не спорьте с изменившимся условием.

## Журнал ошибок

| Задача / паттерн | Причина ошибки | Что изменить | Повтор |
| --- | --- | --- | --- |
| Поиск границы / binary search | Смешал включённую и исключённую правую границу | Перед кодом записать инвариант | Через 3 дня |
| Подстрока / window | Не обновил частоту при сжатии | Проверять повторяющиеся символы | Через неделю |

Интервалы повторения — пример, адаптируйте под свой график. За день до секции полезнее разобрать знакомые ошибки и отдохнуть, чем пытаться освоить новый большой раздел.

## Что сделать прямо сейчас

- [ ] Уточните, алгоритмический ли у вас live coding.
- [ ] Решите две диагностические задачи без подсказок.
- [ ] Выберите три слабых паттерна и по два упражнения на каждый.
- [ ] Проведите пробную секцию с объяснением вслух.
- [ ] Создайте журнал ошибок и даты повторения.
