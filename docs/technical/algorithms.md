# Алгоритмы и live coding

Алгоритмический отбор встречается в крупных технологических компаниях и отдельных командах. [Яндекс включает алгоритмические задачи в найм бэкенда](https://yandex.ru/jobs/interview/backend); в другом месте live coding может быть API, исправлением бага или SQL. Уточняйте формат заранее.

## Сначала проверьте стартовую точку

Решите без подсказок незнакомые задачи на массив и хеш-таблицу, проговаривая сложность и тесты. Определите причину затруднения: выбор структуры, алгоритм, код или крайний случай.

Используйте знакомый разрешённый язык. Повторите коллекции, сортировку, сравнение, пустые значения и числа.

## Карта паттернов

| Паттерн | Когда полезен | Проверочный вопрос |
| --- | --- | --- |
| Hash map / set | Частоты, поиск пары, дубликаты | Что хранится в ключе и сколько памяти потребуется? |
| Two pointers | Отсортированные последовательности, движение с двух концов | Почему указатель можно сдвинуть, не пропустив ответ? |
| Sliding window | Подотрезок с ограничением | Когда окно можно сжать и поддерживать условие? |
| Prefix sums | Повторные суммы диапазонов | Где нулевой префикс и как избежать ошибки границ? |
| Binary search | Упорядоченность или монотонный ответ | Какой инвариант и что происходит на пустом диапазоне? |
| Stack / queue | Скобки, обход, монотонная структура | Что означает элемент и когда удаляется? |
| BFS / DFS | Деревья, графы, связность | Как отмечаются посещённые вершины, есть ли циклы? |
| Heap | Лучшие k элементов, приоритеты | Почему не полная сортировка? |
| Intervals | Пересечения, объединение, расписание | Как определено касание границ? |
| Backtracking | Перебор вариантов с ограничениями | Где отсечение и восстановление состояния? |
| Dynamic programming | Повторяющиеся подзадачи | Что означает состояние, переход и базовый случай? |

Сложную динамику и соревнования добавляйте только по требованиям отбора после освоения базы.

## Сколько задач решать

Стартовый ориентир — 25–40 задач на основные паттерны с повторением ошибок. Расширяйте набор, если алгоритмы важны в целевом отборе.

Задача освоена, когда вы объясняете и пишете решение без просмотра. После лимита времени изучите подсказку, запишите идею и повторите позже.

Начните с готовой [подборки 50 задач](../interview-bank/leetcode-50.md) или практикуйтесь в [CodeRun](https://coderun.yandex.ru/) и [LeetCode](https://leetcode.com/studyplan/top-interview-150/). Не откладывайте отклики до завершения плана.

## Поведение на секции

1. Перескажите задачу. Уточните размер входа, повторы, пустой ввод, диапазон чисел и ожидаемый формат результата.
2. Покажите простой корректный подход и оцените время/память.
3. Предложите улучшение и объясните его идею до кода.
4. Согласуйте решение с интервьюером. Пишите читаемо, называйте инвариант.
5. Проверьте обычный пример, пустой/минимальный ввод, повторения и границы.
6. Сравните итоговую сложность с требованиями и обозначьте ограничения.

Если застряли, проговорите проблему и следующую гипотезу. Полученную подсказку используйте открыто.

## Журнал ошибок

| Задача / паттерн | Причина ошибки | Что изменить | Повтор |
| --- | --- | --- | --- |
| Поиск границы / binary search | Смешал включённую и исключённую правую границу | Перед кодом записать инвариант | Через 3 дня |
| Подстрока / window | Не обновил частоту при сжатии | Проверять повторяющиеся символы | Через неделю |

Перед секцией разберите знакомые ошибки вместо нового большого раздела.

## Что сделать прямо сейчас

- [ ] Уточните, алгоритмический ли у вас live coding.
- [ ] Решите две диагностические задачи без подсказок.
- [ ] Выберите три слабых паттерна и по два упражнения на каждый.
- [ ] Проведите пробную секцию с объяснением вслух.
- [ ] Создайте журнал ошибок и даты повторения.
